# 로컬 PostgreSQL 미실행으로 백엔드 시작 실패

- **상태:** 해결 (백엔드 기동과 회원가입 HTTP 요청 확인)
- **발견일:** 2026-10-07
- **관련 기능:** Issue #3 w2 회원가입 실행 검증

## 문제와 관찰

- IntelliJ에서 백엔드를 실행하자 Flyway 초기화 중 `localhost:5432` 연결이 거부됐다 (`SQL State 08001`). 컨트롤러나 회원가입 요청을 처리하기 전의 시작 실패였다.
- `docker compose ps`에 실행 중인 서비스가 없었고, 로컬 5432 포트 연결 검사도 실패했다.
- 이전 Gradle 빌드의 DB 통합 테스트는 별도의 Testcontainers PostgreSQL을 사용하므로 로컬 Compose DB의 실행 여부를 검증하지 않는다.

## 원인과 조치

- 로컬 PostgreSQL 컨테이너가 실행 중이지 않았다.
- 저장소 루트에서 `docker compose up -d postgres`로 컨테이너를 시작했다. 기존 데이터를 삭제하는 명령은 사용하지 않았다.

## 검증과 남은 내용

- 컨테이너 상태가 `healthy`이고 `127.0.0.1:5432` 연결이 가능함을 확인했다.
- 백엔드 `bootRun`에서 Flyway V1 적용과 8080 포트 기동 로그를 확인한 뒤 확인용 프로세스를 종료했다.
- 이후 사용자가 Postman에서 회원가입 `201`과 중복 가입 `409`를 확인했다. 보안 경로의 별도 문제와 검증은 [관련 기록](2026-10-07-sign-up-security-entry.md)에 남겼다.
- 확인용 `bootRun`의 성공과 Postman 응답은 확인했지만, 앞서 실패했던 IntelliJ 실행을 같은 절차로 다시 검증했는지는 기록이 없다.
