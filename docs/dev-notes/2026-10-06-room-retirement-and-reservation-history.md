# 예약 이력이 있는 회의실의 운영 종료

- **상태:** 설계 결정, 구현·검증 전
- **발견일:** 2026-10-06
- **관련 기능:** Phase 2 회의실 삭제와 예약 이력

## 판단할 문제

회의실을 더는 예약받지 않을 때 기존 예약 이력을 어떻게 보존할지 결정해야 했다. 특히 앞으로 잡힌 예약이 있으면 회의실 삭제와 그 예약들의 처리가 함께 영향을 받는다.

## 선택과 이유

- 회의실 데이터를 물리적으로 삭제하는 대신 운영 종료 상태로 보관한다. 예약 이력을 남기기로 한 서비스 결정과 맞고, 이력이 참조하는 회의실 정보를 계속 사용할 수 있다.
- 앞으로 잡힌 예약이 있으면 owner에게 먼저 확인을 요청한다. 중단하면 변경하지 않고, 진행하면 해당 예약을 모두 강제 취소하되 이력은 남긴다.
- 운영 종료된 회의실은 새 검색·예약에서 제외한다. 취소된 회원에게는 예약 상태 표시와 별도로 서비스 안 알림을 제공한다.

물리 삭제를 택하면 이력을 유지할 별도의 처리 방식이 필요하다. 반대로 운영 종료 상태를 택하면 조회·예약 경로에서 종료된 회의실을 빠짐없이 제외해야 한다. 이는 설계상 예상되는 영향이며 아직 실행 결과는 아니다.

## 구현에서 확인할 것

- owner가 확인을 중단했을 때 회의실과 예약이 모두 그대로인지 확인한다.
- 진행했을 때 앞으로 잡힌 예약의 취소 이력, 운영 종료 상태, 검색·예약 제외, 회원 알림을 함께 확인한다.
- 저장 표현, 처리 경계, 알림 실패 처리와 확인 중 예약이 바뀌는 경우는 구현 전에 별도로 결정한다. 현재 특정 데이터베이스 구조나 동시성 해결 방식은 확정하지 않았다.
